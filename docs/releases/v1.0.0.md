# g2rain-cms v1.0.0

## 组件定位与交付范围

`g2rain-cms` 是 G2rain（谷雨）开源智能体平台中的 CMS 内容管理领域服务，而不是整个平台、IAM、Gateway、前端应用或智能体运行时。它以 API/Biz/Startup 三模块交付站点、内容空间、栏目、页面、文章、分类、标签及文章标签关系的查询、写入、状态变化和持久化能力。管理端由 `g2rain-cms-app` 提供；调用方应经 IAM 和 Gateway 接入。

## 构建和运行事实

- 项目版本：根 `pom.xml` 的 Maven `project.version` 为 `1.0.0`；模块继承同一版本。
- 关键框架：Java 25、Spring Boot 4.1.2、Spring Cloud 2025.1.4、Maven 3.9+。
- 运行依赖：MySQL 8.0.13+、Redis 和 Nacos；默认服务端口为 `8080`，入口为 `com.g2rain.Application`。
- 容器：Jib 使用 `eclipse-temurin:25.0.4.1_1-jre`，声明端口 `8080`，包含 Spring Boot Startup 模块的类、依赖和资源，并使用相同的 Jib 配置进行本地 Docker 构建与 CI 推送。
- OCI 元数据：`org.opencontainers.image.source=https://github.com/g2rain/g2rain-cms`、Apache-2.0 许可证、title `g2rain-cms` 和 version `1.0.0`。

## 镜像、顺序与权限

镜像地址为 `ghcr.io/g2rain/g2rain-cms`。成功发布会推送 `:1.0.0` 与 `:sha-<完整提交 SHA>`；不推送 `latest`。先将本发布说明、版本和工作流改动合入 `main` 并完成验证，再从该提交创建 `v1.0.0` tag。标签推送触发工作流；工作流不创建 GitHub Release，也不部署服务。

仓库许可证为 Apache License 2.0。首次成功推送后，在 GitHub Packages 的 **Package settings → Change visibility → Public** 设置公开；若组织管理员限制此操作，请联系管理员。若已有包推送返回 `denied`，先检查 **Package settings → Actions access** 是否已授予本仓库写入权限，以及组织 Packages 策略。

## 配置与安全

最终镜像会包含 Jib 组装的应用类、依赖和 `g2rain-cms-startup/src/main/resources` 中的运行资源。因此已跟踪的 `application.yml` 和 `application-dev.yml` 会进入镜像；其中前者有 Nacos 默认用户名/密码回退值，后者有本地 MySQL 用户名和密码字面量。它们不应作为生产凭据使用。生产环境必须以部署平台 Secret、环境变量或受控 Nacos 配置注入 MySQL、Nacos、Token 与其他密钥，并支持轮换；不要将生产密钥写入镜像、仓库或日志。

## 已知限制与验证状态

当前没有自动化测试源码；`mvn clean verify` 的通过仅证明编译、打包和 source/Javadoc 产物生成，不能证明数据库、Nacos、Redis、Gateway、租户隔离、事务或部署后的集成行为。本发布准备的本地验证会记录在变更交付中；GHCR 推送、匿名拉取、镜像运行和真实部署需在具备相应权限与环境时分别验证。
